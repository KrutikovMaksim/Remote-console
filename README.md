# Remote Console (SSH-подобная утилита для Windows)

Приложение для удаленного доступа к командной строке Windows (cmd.exe) через сетевое соединение. По принципу работы похоже на SSH, но работает только на Windows и использует TCP/IP сокеты.

## Архитектура

```
Клиент (my.exe -c) <--сокеты--> Сервер (my.exe -s)
                                    |
                                    v
                              Дочерний процесс (cmd.exe)
                              <-- именованные каналы (pipes) -->
```

## Возможности

1. **Перенаправление потоков**: Сервер перенаправляет stdin/stdout/stderr дочернего процесса (cmd.exe) через именованные каналы
2. **Сетевое взаимодействие**: Клиент и сервер обмениваются данными через TCP сокеты
3. **Windows Служба**: Сервер может работать как Windows Service (фоновый процесс)

## Использование

### Режим сервера (интерактивный)
```bash
my.exe -s [port]
```
Порт по умолчанию: 8888

### Режим клиента
```bash
my.exe -c <адрес_сервера> [port]
```
Пример: `my.exe -c 127.0.0.1 8888`

### Режим службы Windows

#### Установка службы
```bash
my.exe -install
```
**Примечание:** Требуются права администратора

#### Запуск службы
```bash
my.exe -start
```

#### Остановка службы
```bash
my.exe -stop
```

#### Удаление службы
```bash
my.exe -uninstall
```

#### Запуск как служба (вызывается Service Control Manager)
```bash
my.exe -s -service
```
**Примечание:** Этот режим обычно вызывается автоматически Windows при запуске службы

## Детали реализации

### 1. Перенаправление потоков через каналы
- Использует `CreatePipe()` для создания анонимных каналов
- Использует `CreateProcess()` с флагом `STARTF_USESTDHANDLES` для перенаправления stdin/stdout/stderr
- Дескрипторы правильно наследуются и управляются

### 2. Сетевое взаимодействие
- Использует Winsock2 API для работы с TCP сокетами
- Сервер прослушивает указанный порт (по умолчанию 8888)
- Клиент подключается к адресу сервера
- Потоки обрабатывают двунаправленную связь:
  - Сокет → Канал (ввод в дочерний процесс)
  - Канал → Сокет (вывод из дочернего процесса)
  - Ошибки → Сокет (stderr из дочернего процесса)

### 3. Windows Служба
- Реализует интерфейс Windows Service Control Manager (SCM)
- Службу можно установить, запустить, остановить и удалить
- Служба запускает сервер в фоновом режиме

## Требования

- Операционная система Windows

- Права администратора (для установки службы)

## Как это работает

### Процесс подключения клиента к серверу:

1. **Клиент подключается:**
   - Клиент создает TCP сокет и подключается к серверу
   - Сервер принимает подключение через `accept()`

2. **Сервер создает дочерний процесс:**
   - Сервер создает три именованных канала (stdin, stdout, stderr)
   - Запускает cmd.exe с перенаправленными потоками
   - Дочерний процесс наследует дескрипторы каналов

3. **Создание потоков для передачи данных:**
   - **Поток 1**: Читает данные из сокета клиента и записывает в stdin cmd.exe
   - **Поток 2**: Читает данные из stdout cmd.exe и отправляет в сокет клиента
   - **Поток 3**: Читает данные из stderr cmd.exe и отправляет в сокет клиента

4. **Интерактивная работа:**
   - Команды, введенные пользователем на клиенте, отправляются на сервер
   - Сервер передает их в cmd.exe через канал
   - Вывод cmd.exe отправляется обратно клиенту
   - Клиент отображает вывод в консоли пользователя

5. **Завершение:**
   - При отключении клиента все потоки завершаются
   - Дочерний процесс cmd.exe завершается
   - Каналы и сокеты закрываются
   - Сервер готов к следующему подключению

## Важные замечания по безопасности

**ВНИМАНИЕ:** Это демонстрационное приложение. Для использования в production необходимо добавить:

- **Аутентификация/авторизация** - проверка пользователя перед подключением
- **Шифрование (TLS/SSL)** - защита данных при передаче по сети
- **Валидация входных данных** - проверка команд перед выполнением
- **Ограничение скорости** - защита от злоупотреблений
- **Логирование и мониторинг** - запись всех действий для аудита
- **Ограничение доступа** - только разрешенные IP-адреса/пользователи
- **Изоляция процессов** - ограничение прав дочернего процесса

**БЕЗ ЭТИХ МЕР ПРОГРАММА НЕ БЕЗОПАСНА ДЛЯ ИСПОЛЬЗОВАНИЯ В СЕТИ!**

## Устранение неполадок

### Проблема: "bind failed" при запуске сервера
**Решение:** Порт уже занят. Попробуйте другой порт:
```bash
my.exe -s 8889
```

### Проблема: "connect failed" при подключении клиента
**Решение:** 
- Убедитесь, что сервер запущен
- Проверьте правильность адреса и порта
- Проверьте настройки файрвола

### Проблема: "OpenSCManager failed" при установке службы
**Решение:** Запустите программу от имени администратора (права администратора)

### Проблема: Служба не запускается
**Решение:**
- Проверьте логи событий Windows (Event Viewer)
- Убедитесь, что порт не занят
- Проверьте, что служба установлена правильно
